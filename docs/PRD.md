# PRD: 소프트웨어 시험 절차 스케줄링 서비스

## 1. 목적

시험 담당자가 외부 시험 절차를 가져와 캘린더에 배치하고, 시험 항목별 실제 실행 시간과 결과를 추적할 수 있게 한다.

이 제품은 자동 최적화 스케줄러가 아니라 사람이 드래그앤드롭으로 계획을 조정하는 운영 도구다.

## 2. 사용자

| 사용자 | 필요 |
| --- | --- |
| 시험 담당자 | 오늘/이번 주 배정된 시험을 확인하고 실행 상태를 기록한다 |
| 스케줄 관리자 | 시험 절차를 동기화하고 담당자/장소/시간표를 배치한다 |
| 프로젝트 관리자 | 버전별 시험 계획, 잔여 시간, 완료/실패/보류 결과를 확인한다 |

## 3. 핵심 업무 흐름

1. 관리자가 시험 절차를 동기화한다.
2. 동기화된 procedure가 캘린더 옆 큐에 표시된다.
3. 관리자가 procedure 또는 일부 시험 항목를 시간표로 드래그한다.
4. 필요하면 블록을 이동, 리사이즈, 분리, 잠금 처리한다.
5. 시험 담당자가 실행 화면에서 시험 항목를 시작한다.
6. 담당자가 일시정지/재개/완료를 기록한다.
7. 완료 시 pass/fail/block 수와 실제 소요 시간이 저장된다.

## 4. 기능 요구사항

### 4.1 시험 절차 동기화

서비스는 DynReady 연동을 지원한다.

| 연동 | 요구사항 |
| --- | --- |
| `dyn_ready` | `/dyn_ready/std-list/grouped` 응답을 읽는다 |

동기화 규칙:

1. `document_id`와 `test_round` 조합으로 procedure를 생성/갱신한다.
2. DynReady의 `exam_no`를 내부 `test_round`로 변환한다.
3. 같은 `test_round` 안에서는 시험 항목 ID가 중복되면 안 된다.
4. 다른 `test_round`에서는 같은 시험 항목 ID를 허용한다.
5. 이미 배치된 시험 항목가 외부 데이터에서 빠져도 즉시 삭제하지 않고 경고한다.

### 4.2 TestProcedure 관리

`test_plan.json` 최상위의 `version_id`는 현재 전체 시험 사이클의
OFP/스케줄 버전을 의미한다.

TestProcedure는 문서/절차 단위이며 다음 정보를 가진다.

| 필드 | 설명 |
| --- | --- |
| `document_id` | 외부 문서 ID |
| `document_name` | 표시 이름 |
| `test_round` | 시험 차수 |
| `assignee_names` | 시험 담당자 이름 배열 |
| `test_items` | 시험 항목 목록 |
| `estimated_minutes` | 시험 항목 예상 시간 합 |
| `remaining_minutes` | 아직 배치되지 않은 시간 |
| `memo` | 메모 |

진행 상태는 procedure에 직접 저장하지 않고 실행 데이터에서 계산한다. `status='cancelled'`는 외부 삭제/취소 표시 용도로만 사용한다.

### 4.3 캘린더

| 뷰 | URL | 요구사항 |
| --- | --- | --- |
| 일간 | `/schedule/` | 장소별 컬럼, 시간 슬롯, 블록 이동/리사이즈 |
| 주간 | `/schedule/week` | 평일 5일과 장소 서브컬럼 |
| 월간 | `/schedule/month` | 평일 중심 월간 일정 표시 |

공통 요구사항:

1. 장소 필터를 제공한다.
2. 필터 선택은 새로고침 후에도 유지한다.
3. 휴식/점심 시간은 시간 계산과 UI 표시에서 반영한다.
4. 잠긴 블록은 이동/리사이즈/일괄 이동 대상에서 제외한다.

### 4.4 드래그앤드롭

지원해야 하는 조작:

1. 큐 procedure를 시간표에 배치한다.
2. 여러 시험 항목 중 일부만 선택해 배치한다.
3. 기존 블록을 같은 날 또는 다른 날로 이동한다.
4. 기존 블록을 큐로 되돌린다.
5. 블록을 리사이즈한다.
6. 특정 날짜 이후의 블록을 하루 단위로 일괄 이동한다.
7. 업무 종료 시간을 넘으면 사용자 확인 후 당일 업무 종료 시각으로 제한하고, 미배치 시간은 큐에 남긴다.

리사이즈는 계획 시간이 아니라 실제 배정 시간 변경으로 처리하며, 단순히 큐 잔여 시간을 복원하지 않는다.

### 4.5 시험 항목 분할

하나의 procedure는 여러 시험 항목를 가질 수 있고, 시험 항목 단위로 분할 배치할 수 있어야 한다.

요구사항:

1. 큐 드래그 시 시험 항목 선택 피커를 제공한다.
2. 이미 배치된 시험 항목는 배치됨으로 표시한다.
3. 시험 항목를 다른 블록으로 옮기면 기존 블록에서 제거한다.
4. 블록 상세에서 이 블록/다른 블록/미배치 상태를 구분한다.
5. `test_item_ids=null` 블록은 전체 시험 항목를 포함한 것으로 본다.
6. 미배치 시험 항목가 있으면 큐에는 그 잔여 시간만 표시한다.

### 4.6 단순 블록

시험 외 일정(준비, 회의 등)을 생성할 수 있어야 한다.

단순 일정은 제목과 시간 중심으로 관리되며, 큐에 올릴 때는 `is_simple=true` procedure로 만들고 캘린더에 직접 만들 때는 `is_simple=true`, `title`, `procedure_id=null` 블록을 사용한다.

### 4.7 실행 관리

실행 화면은 procedure 시험 항목별 실행 상태를 제공해야 하며, 날짜/장소 필터를 선택하면 배치된 block 기준으로 좁혀 보여준다.

상태:

```text
pending -> in_progress -> paused -> in_progress -> completed
```

요구사항:

1. 실행 레코드가 없거나 pending 레코드만 있으면 pending으로 표시한다.
2. 시작 시 `(test_item_id, procedure_id)` 조합으로 실행 레코드를 만든다.
3. 재시작하면 기존 레코드를 초기화한다.
4. 일시정지 이력은 저장하지 않고 최초 시작, 최종 종료, 누적 실제 시험시간만 기록한다.
5. 완료 시 fail/block/pass 수를 저장한다.
6. 수행자와 코멘트를 저장할 수 있어야 한다.
7. 완료 후 외부 API 설정이 있으면 실제 소요 시간을 비동기로 전송한다.

### 4.8 내보내기

CSV/XLSX 내보내기를 지원해야 한다.

포함 정보:

1. 날짜/시간/장소/담당자
2. 문서명과 시험 항목 정보
3. 버전 정보
4. 분할 블록의 `N/M` 표시
5. 상태와 메모

## 5. 데이터 요구사항

영속 데이터는 domain 타입으로 정의하고 JSON 파일로 저장한다.

| 파일 | 요구사항 |
| --- | --- |
| `test_plan.json` | 시험 사이클 버전, procedure, 캘린더 블록 |
| `test_executions.json` | 실행 상태와 결과 |
| `settings.json` | 근무 시간과 화면 설정 |

파일 쓰기는 잠금과 원자적 파일 교체를 사용해야 한다.
장소 이름은 procedure와 schedule block에 직접 저장하며 별도 장소 파일을 두지 않는다.

## 6. 설정 요구사항

관리자는 다음 값을 수정할 수 있어야 한다.

```json
{
  "work_start": "08:00",
  "work_end": "17:00",
  "actual_work_start": "08:30",
  "actual_work_end": "16:30",
  "lunch_start": "12:00",
  "lunch_end": "13:00",
  "breaks": [{"start": "10:00", "end": "10:15"}],
  "grid_interval_minutes": 15,
  "max_schedule_days": 21,
  "block_color_by": "status"
}
```

`block_color_by`는 `assignee`, `location`, `status`를 지원한다.

## 7. 비기능 요구사항

| 항목 | 요구사항 |
| --- | --- |
| 로컬 실행 | `python3 run.py`로 개발 서버 실행 |
| 기본 포트 | 5001 |
| 저장 안정성 | 임시 파일 작성 후 원자적 파일 교체 |
| 동시 접근 | `portalocker`로 파일 잠금 |
| 테스트 | pytest 기반 회귀 테스트 유지 |
| 포맷 | 현재 저장소에는 별도 포맷터 설정이 없다. 도입 시 설정 파일을 추가한다 |
| 운영 보안 | 운영 환경에서는 `SECRET_KEY`와 외부 API 키를 환경 변수로 설정 |

## 8. 성공 기준

1. 동기화 후 procedure 큐가 최신 절차를 보여준다.
2. 관리자가 시험 항목 단위로 일정을 배치/분리/복귀할 수 있다.
3. 시간표가 휴식 시간과 업무 종료 초과를 반영한다.
4. 실행 담당자가 시험 항목별 타이머와 결과를 기록할 수 있다.
5. procedure 상태가 실행 결과와 모순되지 않는다.
6. 내보내기 파일이 현재 캘린더와 버전 정보를 반영한다.
