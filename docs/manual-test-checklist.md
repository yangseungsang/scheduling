# 사용자 관점 수동 테스트 체크리스트

자동화 테스트 통과 후 실제 화면에서 핵심 흐름을 확인하기 위한 체크리스트다.
각 항목은 브라우저 새로고침을 포함해 실제 사용 순서대로 점검한다.

## 1. 데이터 동기화

- 관리자 화면에서 dyn_ready 동기화를 실행한다.
- `/dyn_ready/std-list/grouped` 응답의 `identifiers[].pf_num` 값이 task 식별자의 총 건수로 반영되는지 확인한다.
- 같은 `doc_id`가 여러 `exam_no`로 나뉘면 문서명이 `2차`, `3차`처럼 구분되어 보이는지 확인한다.
- 이미 스케줄에 배치된 식별자가 외부 데이터에서 사라진 경우, 배치된 항목이 임의로 삭제되지 않는지 확인한다.

## 2. 스케줄 배치

- 스케줄 주간/일간 화면에서 task를 장소와 날짜에 배치한다.
- 여러 식별자를 가진 task는 일부 식별자만 선택해 분리 배치할 수 있는지 확인한다.
- 기존 블록을 다른 날짜, 시간, 장소로 이동했을 때 execution 화면의 장소와 날짜가 같이 바뀌는지 확인한다.
- 블록을 큐로 되돌렸을 때 해당 식별자가 execution 목록 필터에서 제외되는지 확인한다.

## 3. Execution 목록

- `/execution/`에 처음 진입했을 때 시작하지 않은 항목도 총 건수가 0이 아닌 실제 `pf_num` 값으로 보이는지 확인한다.
- 시작하지 않은 항목의 Pass, Fail, Block은 각각 0으로 보이는지 확인한다.
- 날짜, 장소, 검색 필터를 바꿔도 총 건수와 Pass/Fail/Block 표시가 유지되는지 확인한다.
- 같은 식별자 ID가 다른 차수 또는 다른 task에 있을 때 문서명과 차수별로 구분되는지 확인한다.

## 4. Execution 상세

- 시작 전 상세 화면에서 총 건수가 표시되는지 확인한다.
- 시작 전에는 Fail/Block 입력이 비활성화되고 Pass는 0으로 보이는지 확인한다.
- 시험 시작 후 총 건수가 유지되고 Fail/Block 값을 입력하면 Pass가 `총 건수 - Fail - Block`으로 계산되는지 확인한다.
- 일시정지, 재시작, 완료 후 목록으로 돌아왔을 때 상태와 결과 수치가 일치하는지 확인한다.
- 완료 후 초기화하면 기록은 사라지지만 총 건수는 그대로 유지되는지 확인한다.

## 5. 실행 충돌과 사용자 정보

- 같은 사용자가 다른 시험을 진행 중일 때 새 시험 시작이 막히는지 확인한다.
- 다른 사용자의 진행 중 시험은 현재 사용자의 다른 시험 시작을 막지 않는지 확인한다.
- 수행자와 코멘트를 시작 전에 입력한 뒤 시작했을 때 값이 유지되는지 확인한다.
- 완료 후 코멘트 아이콘이 목록에 표시되고 툴팁으로 내용이 보이는지 확인한다.

## 6. 회귀 확인

- 기존 완료된 실행 기록의 Fail, Block, Pass, 총 건수가 깨지지 않는지 확인한다.
- 페이지 새로고침 후에도 타이머, 상태, 수행자, 코멘트가 서버 값과 일치하는지 확인한다.
- 모바일 또는 좁은 화면에서 execution 목록과 상세 화면의 숫자 영역이 겹치지 않는지 확인한다.
